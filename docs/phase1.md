# REVORA — Phase 1: Payment Intelligence Foundation

## Executive Summary

Phase 1 establishes the production-grade **Payment Intelligence Foundation** for **REVORA (AI-Powered Payment Revenue Recovery)**.

The objective of Phase 1 is to build a robust, reproducible, and leak-free payment dataset generation, validation, and splitting infrastructure. Phase 1 purposefully excludes LLM agents, payment execution, and model training to ensure the core dataset signals are mathematically sound and realistic before building downstream recovery engines.

---

## Key Achievements & Capabilities

1. **Clean Repository Structure**: Modular Python package (`src/data`, `src/utils`), configuration files (`config/dataset_config.yaml`), CLI scripts (`scripts/generate_dataset.py`), documentation (`docs/`), and unit tests (`tests/`).
2. **Deterministic Synthetic Data Generation**:
   - Generates configurable dataset sizes (default: 20,000 transactions; sample: 1,000 transactions).
   - Fully reproducible via deterministic random seeds (`--seed 42`).
3. **Realistic Failure Taxonomy**:
   - Implements 10 failure categories (`SUCCESS`, `TEMPORARY_GATEWAY_FAILURE`, `NETWORK_ERROR`, `INSUFFICIENT_FUNDS`, `BANK_DECLINED`, `AUTHENTICATION_FAILURE`, `FRAUD_RISK_BLOCK`, `EXPIRED_CARD`, `INVALID_PAYMENT_DETAILS`, `UNKNOWN_FAILURE`).
   - Clearly defines retryable vs non-retryable categories.
4. **Data Leakage Mitigation**:
   - Strictly isolates pre-recovery predictive features from target fields (`recovery_probability_target`, `recovered`).
   - Excludes post-recovery outcome fields (`final_recovery_timestamp`, `actual_recovery_action_result`, etc.).
5. **Strict Outcome Separation**:
   - `payment_status` clearly distinguishes `SUCCESS` and `FAILED`.
   - `recovered` and `recovery_probability_target` are designated exclusively for `FAILED` transactions (`NaN` for `SUCCESS`).
6. **Synthetic Ground-Truth Target**:
   - `recovery_probability_target` is explicitly defined as a synthetic ground-truth probability generated by the simulator using realistic behavioral & risk relationship functions.
   - It is NOT an ML prediction.
7. **Automated Validation Pipeline**:
   - Programmatically enforces 10 data quality checks (required columns, missing values, duplicate IDs, non-positive amounts, invalid categories, leakage candidates, etc.).
8. **Reproducible Stratified Splitting**:
   - Splits data into 70% Train, 15% Validation, and 15% Test.
   - Stratifies across both payment status and recovery outcome.
   - Asserts zero transaction ID overlap across splits.
9. **Test Set Protection Protocol**:
   - The test set is strictly locked and held out. It will not be used for feature engineering, threshold selection, hyperparameter tuning, or policy design.
10. **Comprehensive Test Suite**:
   - 100% passing `pytest` suite covering generator, validator, and splitter modules.
